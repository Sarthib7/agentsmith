Three tiers, read top to bottom

Read the graph top to bottom. Optional advisor roles sit above the main-session lead. Logical task scopes sit below it, with results returning for parent verification.

These labels describe public role patterns, not active sessions, provider access, or a fixed swarm size.

  1. TOP

    Optional advisors: Astra, Fable, Grok

    Astra reviews correctness, invariants, and security. Fable reviews architecture, API design, and YAGNI. Grok checks obvious regressions and test gaps. These are optional reviewer roles in the public roster, not evidence that advisors are active.

  2. MIDDLE

    Lead orchestrator: the main session

    The lead owns the plan and cross-slice contracts. It chooses independent typed tasks, gathers returned artifacts, and remains responsible for integration and parent-owned verification.

  3. BOTTOM

    Subagent swarms: logical task scopes

    Each delegated item has a bounded brief and an owner. Workers return results to the lead. The group is illustrative: it makes no claim about live agent count, system capacity, or process isolation.

What this model does not prove

Policy and implementation are different. The intended policy keeps advisors on the main session. Public code analysis also finds per-agent opt-ins, so that policy is not a hard technical boundary.

The ordinary createAgentSession() route is in-process at the pinned public revision. An optional isolation dispatch does not prove operating-system containment.

  1. STATE

    No live activity claim

    This page is an explanation, not telemetry. It does not show active advisors, a running lead, or a live worker swarm.

  2. ACCESS

    No model or account claim

    Model identifiers in dated public examples do not verify current provider settings, subscriptions, credentials, or account access.

  3. BOUNDARY

    No OS isolation claim

    Logical task scopes and an isolation dispatch option do not establish a process, sandbox, or operating-system security boundary.

  4. SCALE

    No capacity claim

    The swarm drawing is a conceptual layer. It is not a measured count, concurrency setting, or promise of available workers.

  5. APPROVAL

    No runtime-lock claim

    The graph marks a human permission boundary. It does not prove publication is enforced by a runtime lock or that a person has already approved it.
