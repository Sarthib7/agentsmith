Five steps. One accountable lead.

Plan before delegation. The lead reads the request, defines the boundaries, and fixes the contracts between independent slices. The plan stays with the lead.

Every handoff should leave enough context and evidence for another person to continue without relying on private chat history.

  1. 01

    Scope the slice

    Write the deliverable, owner, acceptance evidence, and exact file boundary. Decide shared interfaces before parallel work starts.

  2. 02

    Delegate typed work

    Batch only independent slices. Give each agent a self-contained brief and choose the narrowest role that fits. Keep one owner per file.

  3. 03

    Return artifacts

    Workers return files, reports, and readable evidence. Pass large payloads by reference. The artifact records what changed and what remains unknown.

  4. 04

    Verify at the parent

    The lead waits for sibling edits to land, then checks the merged result once. An error or rework request means the work is unresolved. It never grants permission to publish.

  5. 05

    Hand off to a human

    Present the result, observed checks, open risks, and source links. External publication or other consequential action needs a separate human decision.

03 / OPT-IN EXPERIMENT

One experiment, explicitly requested and parent-reviewed.

The harness experiment is process guidance for comparing one instruction variant on a public or synthetic task. A recurring failure may prompt a suggestion; it never starts an experiment without the user's explicit request.

The packaged skill's local reference is canonical. The public workflow guide is a short entry point, not a second copy of the procedure. A public source link does not prove that a skill is installed or discoverable.

Harness experiment processPOLICY · NOT RUNTIME ENFORCEMENT
  1. 01 / REQUEST

    Set the scope

    Start only on an explicit user request. Define one public or synthetic task; a suggestion is not approval.

  2. 02 / FREEZE

    Fix inputs and bounds

    Record code and fixture identities, model, tools, permissions and network, acceptance checks, one metric, the edit surface, and total call, time, and spend limits.

  3. 03 / COMPARE

    Run baseline + candidate

    Default to one run each and one instruction variant. Keep other inputs equal, count every call, and do not retry or loop automatically.

  4. 04 / REVIEW

    Inspect and decide

    The parent inspects artifacts and reruns checks. KEEP_BASE or INCONCLUSIVE preserves the baseline; USE_CANDIDATE is task-local only. Candidate check failures, ties, stale identity, missing evidence, executor errors, or an exhausted limit never adopt.

These instructions do not enforce permissions or budgets. Separate workspaces do not prove an OS sandbox, and one experiment cannot establish general quality, latency, or cost gains.
